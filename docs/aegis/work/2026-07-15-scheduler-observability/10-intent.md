# 调度命令可观测性执行意图

日期：2026-07-15

## 请求结果

为线上后端普通定时调度和持久化批量调度增加低开销、可关闭、故障隔离的命令级可观测性，先积累 24–72 小时数据，再另行设计 IP 级主动限流。

## 范围

- 后端普通定时调度与持久化批量调度。
- 命令级分钟聚合、异常明细、3 天保留、管理员只读 API 与页面。
- 观测模块自身健康指标、实际出口匿名指纹和任务到命令的关联。

## 非目标

- 不改变并发、错峰、延迟、超时、重试、重连、代理和任务排序行为。
- 不修复批量调度代理未实际传入 `GameClient` 的既有问题。
- 不增加主动限频、队列持久化、多进程聚合或浏览器手动任务观测。
- 不保存 Token、命令参数、响应正文、原始代理地址或完整堆栈。

## 风险提示

- SQLite 同步写入可能阻塞事件循环，必须批量短事务并隔离失败。
- 命令、任务、出口维度可能膨胀，必须同时设置内存键数、异常行数和 3 天时间上限。
- 当前本机 Node 24 与 `better-sqlite3@11.10.0` 原生绑定不兼容，数据库集成验证必须在生产一致 Node 或可构建环境补做。
